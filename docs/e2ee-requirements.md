## 1. 背景与目标

ItemLife 是个人及家庭记账应用，管理账户、收支流水、物品、配件、成本与综合看板。目前业务数据以服务器可读取的形式存入 MySQL，余额、成本、看板和利息由后端读取明文后计算。

本次目标是在 Database-Encryption 分支实现账本业务数据的端到端加密：数据在用户设备上加密后上传，在授权用户设备上解密；API、数据库及服务器运行配置中不持有可直接解密账本的数据密钥或解锁密码。

“数据库端到端加密”在本文中指账本业务内容的端到端加密，不表示数据库全部字段不可读，也不等同于 HTTPS、磁盘加密或服务器持有密钥的字段加密。

## 2. 已明确内容与待确认方案

### 2.1 已明确内容

- 以 main 为分析基线，计划在 Database-Encryption 分支实施。
- 目标是端到端加密，本轮交付需求文档，不修改业务代码。
- 账本能力需要结合现有个人数据域与家庭数据域设计。

### 2.2 本文建议的方案，尚待确认

- 保留现有登录密码与 MFA，增加独立账本解锁密码。
- 先完成个人账本闭环，再完成家庭共享及旧数据迁移；个人阶段不宣称家庭账本已加密。
- 第一版解锁密钥仅保存在当前页面内存，刷新后重新解锁。
- 服务器自动结息调整为用户解锁后补算、加密入账。
- 保留记录归属、关系及必要同步元数据为明文，敏感业务内容加密。
- 不向管理员提供账本解密或恢复后门。

以上内容用于形成可评审方案，不视为用户已接受功能变化。第 12 节列出实施前需要确认的决策。

## 3. 范围与保护边界

### 3.1 业务范围

完整交付覆盖账户、分类、收支与转账、分摊、物品与配件、库存使用及退库记录、综合看板、利息、家庭共享、数据迁移和恢复。

既有业务口径继续有效：金额按整数分处理；流水是业务金额的权威来源；余额与成本等结果派生计算；多表联动操作保持原子性；个人及家庭域保持隔离。

### 3.2 字段保护要求

| 数据 | 建议要求 |
| --- | --- |
| 金额、初始余额、利率、分摊金额、采购价格、批次价格及余数 | 必须加密，不保留明文副本或可推导金额的明文汇总 |
| 账户名、自定义分类名、物品名、配件名、备注、退库原因、家庭名称 | 纳入加密范围；派生快照及日志遵循相同要求 |
| 业务日期、交易类型、数量、状态、分类语义标签 | 待确认；是否明文影响筛选、索引及隐私边界 |
| 记录 ID、所属用户或家庭 ID、必要关联 ID | 建议保留明文，用于权限与关系校验 |
| 记录版本、密钥版本、同步时间、删除标记 | 建议保留明文，用于同步、并发与迁移 |
| 登录邮箱、密码哈希、角色、成员关系、会话及 MFA 数据 | 沿用认证体系；不纳入账本内容 E2EE，不因此取消原有保护 |

实施前必须形成逐模型字段清单，覆盖 User、Household、Account、Category、Transaction、TransactionItem、Item、ItemAccessory、AccessoryUsage、InventoryRevert 及相关快照。每个字段标注加密、明文或不适用，并说明明文用途。

保留关系元数据会暴露成员关系、数据量、关联结构和活动时间等信息。不得将本方案描述为隐藏所有元数据。

### 3.3 不属于首版的内容

- 同态加密、服务器对密文金额进行通用计算。
- 可搜索加密、离线编辑及复杂冲突合并。
- 默认记住设备、跨设备无感解锁。
- 对恶意终端、浏览器扩展、XSS 或服务器下发的恶意前端代码作完全防护承诺。

## 4. 用户流程与功能需求

### FR-01 首次启用与恢复准备

用户登录后可启用账本加密，设置并确认独立解锁密码。浏览器生成随机数据密钥，上传包装后的密钥及必要参数，不上传可直接解密的密钥。

启用流程提供独立恢复密钥，并要求用户确认已保存。恢复材料不复用 MFA 恢复码，不写入普通日志或默认浏览器持久化存储。恢复密钥与解锁密码全部丢失且无可用解锁设备时，必须明确提示数据无法恢复。

启用失败不得使现有账本不可访问；有旧数据时必须进入第 8 节的迁移流程。

### FR-02 登录、解锁与锁定

登录与解锁为两个状态。登录成功仅获得访问密文的资格，不能直接查看账本明文。已有加密账本在解锁前显示解锁页，不预加载或显示旧明文页面。

支持手动锁定。退出登录、账号变化、会话失效时清理密钥引用、已解密数据、图表、表单及 KeepAlive 页面缓存。清理期间返回的旧异步请求不得重新写入明文状态。浏览器内存无法保证物理擦除，不作此承诺。

刷新后重新解锁、闲置自动锁定时长、后台标签页锁定策略，按第 12 节确认结果实施。多标签页的登出与锁定应保持一致，不通过标签页消息传输明文密钥。

### FR-03 加密读写

客户端完成敏感数据校验、加密并上传；服务器保存密文，按权限下发；客户端校验密文完整性、解密后展示。

加密载荷包含格式版本、密钥版本、IV、密文与认证标签。记录身份、归属、实体类型等上下文必须受到认证保护，防止密文被移用于其他记录。

错误密码、密文损坏、记录被替换或未知版本必须可识别地失败，不以空数据替代、不自动覆盖原记录、不回退为上传明文。请求重试不产生重复流水。

### FR-04 余额、成本、看板与搜索

加密字段参与的计算与搜索在客户端执行。优先复用 packages/shared 中已有的金额、成本、分摊和利息公式；现有业务结果及舍入口径保持一致。

客户端必须获得计算所需的完整数据范围。不能把当前分页视为全量账本；初始余额、区间前历史流水、分摊及配件事件等依赖必须计入。数据尚未完整时显示加载状态，不展示误导性的完整统计。

名称及备注等密文字段不再由服务器执行模糊搜索；金额排序和敏感条件筛选在客户端进行。同步方案必须处理更新、删除、权限变化和数据域切换。

### FR-05 转账与跨记录联动

保留转账成对写入、流水分摊、内联创建物品、配件批次、库存使用与撤销、退库、删除物品扣减来源流水等现有行为。

客户端解密相关记录，计算完整变更并一次提交密文操作集。服务器校验身份、归属、可访问的关联关系和预期版本，并通过数据库事务全部提交或全部回滚。

并发冲突应提示刷新重试，不能静默覆盖。客户端不得修改其他个人或家庭域记录。服务器看不到金额后无法验证金额守恒，必须保留这一限制：客户端负责数值校验及读取后的业务校验，不能宣称对恶意授权客户端提供与明文后端相同的数值约束。

### FR-06 利息

建议用户解锁后检测待结息区间，在客户端计算并生成加密利息流水。历史余额、计息区间、舍入和不足一分处理维持现有口径；跨多日补结不漏算，多个设备同时补结不重复入账。

服务器仍可检查可见的结息标记、记录版本和幂等约束，但不得为延续定时任务而保存明文金额、利率或数据密钥。若要求所有客户端离线时仍准时结息，需单独决策可信计算端及其密钥权限，不能默认兼容。

### FR-07 修改密码与恢复

修改登录密码或管理员重置登录密码，不直接修改或丢弃账本密钥。修改解锁密码时重新包装数据密钥，成功后原解锁密码不得解开当前服务端保存的包装副本。

修改解锁密码不能撤销攻击者已经取得的旧密钥、旧包装副本和旧密文。怀疑数据密钥泄漏时，需要执行密钥轮换及必要的数据重加密。

恢复流程在客户端验证恢复材料，解开数据密钥并设置新解锁密码；失败不得覆盖有效密钥记录。恢复密钥是否轮换及其失效规则需明确。

### FR-08 家庭授权与撤销

个人账本和各家庭账本使用独立密钥。家庭创建者在客户端创建家庭密钥；新成员加入后，只有完成客户端密钥授权才可解密。邀请码只负责成员资格，不承载或派生家庭密钥。

建议每名用户建立加密密钥对，私钥由个人解锁体系保护；由持有家庭密钥的授权成员为新成员包装家庭密钥。必须提供可信公钥确认机制，不能只信任服务器可替换的公钥。

现有 owner、admin、member 的数据操作权限保持不变；谁可以批准密钥分发需确认。等待授权、授权失败、家庭锁定与授权完成应有明确界面状态。

退出或移除成员后，服务器立即拒绝其后续访问，剩余授权成员执行家庭密钥轮换。轮换完成前禁止继续用旧密钥写入新数据；轮换失败可恢复且不损坏账本。

已下载的明文、旧密钥和旧密文无法远程收回；即使重加密历史数据，也不能消除被移除成员已保存的副本。最后一个持有可用家庭密钥的成员丢失密钥时，家庭恢复路径必须有明确定义。

### FR-09 管理、删除与日志

管理员继续管理注册、账号、角色及会话，不获得账本解密权限。停用、个人永久删除和家庭删除继续按现有权限与事务范围执行，并清理相应密文及密钥包装记录。

家庭名称加密后，删除时的完整名称确认在客户端执行；服务器仍必须验证身份和删除权限，不把客户端名称比较当作授权依据。

审计保留操作类型、操作者、记录 ID、结果等必要信息，不记录敏感名称、金额、解锁密码、恢复密钥或明文请求体。覆盖应用日志、异常、代理日志及未来监控采集配置。

## 5. 安全与技术约束

- 数据内容建议使用浏览器 Web Crypto 的 AES-256-GCM；同一密钥下不得复用 IV，认证标签不得关闭。
- 解锁密码建议使用 Argon2id 派生包装密钥，独立随机盐及带版本参数随包装副本保存；实际参数通过目标手机和桌面设备测量确定，不直接照搬后端配置。
- 浏览器的加密依赖应采用维护中的成熟实现，不自创算法。现有 Node argon2 依赖不能直接视为浏览器实现。
- 不从 JWT、邮箱、用户 ID、服务器环境密钥或已交给服务器的登录密码直接派生账本密钥。
- 后端继续校验认证、角色、归属、关联 ID、载荷大小、格式版本及并发版本；密文不能绕过权限。
- 解密后对数据结构、金额范围、引用关系及业务约束再次校验；GCM 认证通过不等于业务内容合法。
- 部署提供 HTTPS 和安全上下文，避免依赖普通内网 IP 的 HTTP 使用浏览器加密能力。
- 不把解锁密码及未包装密钥放入 localStorage、URL、Cookie、日志或服务端 Redis。首版不持久化已解密业务数据。
- GCM 防止未经授权的密文修改，不独自解决恶意服务器回滚历史记录、隐瞒删除或向不同设备返回不同版本的问题；该限制必须记录。

## 6. 数据与接口变更要求

保留现有业务实体及必要关系，建议以每实体一份敏感载荷减少逐字段密文管理。新增按个人或家庭归属的密钥包装记录、密钥版本与并发版本；家庭支持每成员的包装副本。

接口需覆盖初始化、获取包装密钥、重新包装、恢复、密文同步、原子批量写入、家庭密钥授权及轮换。具体路径和数据库列名在设计阶段确定，本文不预设实现。

金额继续使用整数分。序列化不得产生浮点精度损失，必要时使用整数字符串并验证范围。不得在密文之外保留初始余额、统计余额或其他金额副本以规避计算改造。

接口必须显式区分明文旧版本、迁移中及加密版本，防止旧客户端继续提交明文或误读密文。已启用的账本禁止降级写入明文。

## 7. 界面与异常要求

| 场景 | 用户可见行为 |
| --- | --- |
| 首次启用 | 说明保护范围、恢复责任，完成密码确认和恢复材料保存 |
| 已登录未解锁 | 展示解锁页，不展示缓存账本 |
| 解锁密码错误 | 提示解锁失败，允许重试或进入恢复 |
| 密文损坏或版本不支持 | 提示具体记录或范围无法读取，保留原始数据，禁止覆盖 |
| 新家庭成员尚未获密钥 | 显示等待授权，不显示空账本造成误解 |
| 并发版本冲突 | 提示数据已变化，刷新重算；不自动覆盖 |
| 数据未同步完整 | 显示同步进度，统计不冒充完整结果 |
| 会话失效或成员权限撤销 | 停止同步、锁定相关数据并清理可控缓存 |
| 迁移中断 | 展示可恢复状态，恢复后继续或安全终止 |

输入框、错误信息、锁定及恢复流程应支持键盘、移动设备及辅助技术。不得以安全为由移除现有基本可访问性。

## 8. 旧数据迁移与备份

1. 迁移前备份数据库并验证恢复路径，记录账本与版本状态。
2. 对目标账本冻结业务写入，阻止其他设备及旧客户端继续写入；个人与家庭按数据域处理。
3. 授权客户端分批获取旧数据，校验、加密并上传；服务端只提供既存明文，不参与新密钥生成或解密。
4. 迁移进度持久化，重试不重复记录；中断后可继续，切换前保持原始数据可恢复。
5. 核对记录数量、关联关系及迁移前后余额、成本、看板和利息结果；验证抽样解密及恢复材料。
6. 全部校验通过后原子切换数据域状态，阻止明文接口与旧定时任务，再清理在线明文列或副本。
7. 按确认的保留周期处理旧备份、binlog、历史日志及导出；明确何时才能声称服务器历史明文已清理。

迁移期间服务器原本掌握的明文不会因启用 E2EE 自动消失。切换后若继续接受加密写入，不能简单回滚到过期明文备份；回滚必须保护新增数据，并由用户明确接受恢复方案。

加密备份的恢复应同时包含密文、必要元数据及包装密钥记录，解密仍依赖用户恢复材料。家庭迁移授权人与密钥恢复负责人必须明确。

## 9. 验收标准

| 编号 | 验收内容 | 通过条件 |
| --- | --- | --- |
| AC-01 | 个人加密闭环 | 新建、读取、编辑及删除账户和流水正常；请求与数据库无范围内敏感明文 |
| AC-02 | 密钥边界 | 仅持数据库、Redis、配置和日志无法直接恢复账本；解锁密码与原始密钥未上传 |
| AC-03 | 错误与篡改 | 错密码、错误密钥、修改密文、替换记录或归属均失败，不覆盖原始记录 |
| AC-04 | 计算一致 | 相同样例的余额、成本、趋势、分摊及利息与基线一致，分页不截断计算依赖 |
| AC-05 | 原子与并发 | 转账和联动操作失败全部回滚；重复提交不重记；旧版本提交被拒绝 |
| AC-06 | 登录与恢复 | 新设备可解锁；登录密码重置不破坏密钥；恢复成功和失败路径均符合约定 |
| AC-07 | 锁定与隔离 | 锁定、退出、换账号后旧页面和晚到响应不显示或恢复旧明文；个人与家庭隔离 |
| AC-08 | 家庭授权 | 加入但未获密钥不可解密；可信公钥确认可验证；授权后可正常共享 |
| AC-09 | 成员撤销 | 权限立即撤销；轮换后移除成员不能解密新写入数据；轮换中断可恢复 |
| AC-10 | 利息补结 | 多日补结结果一致，多设备并发不重复；服务器不再解密计算 |
| AC-11 | 日志与缓存 | 审计、异常及浏览器持久化中无范围内敏感明文和原始密钥 |
| AC-12 | 迁移与恢复 | 中断续传、失败回退、成功切换、拒绝旧客户端及备份恢复通过验证 |
| AC-13 | 兼容与性能 | 约定的浏览器、移动设备及数据量下通过读写、解锁和统计测试 |

测试优先复用现有 smoke:auth、smoke:ledger、smoke:items、smoke:m4m5、smoke:site-admin 的业务样例与内存替身，增加浏览器加密、真实 MySQL 事务迁移及端到端用户流程验证。不能仅用加密解密单元测试替代业务验收。

性能验收前确定支持的浏览器版本、最低手机配置、小型及大型账本样本、解锁和首屏等待阈值。未确定前不得承诺具体性能数字。

## 12. 实施前待确认决策

| 决策 | 建议 | 影响 |
| --- | --- | --- |
| 独立解锁密码 | 接受 | 多一步解锁，保持服务器无法借登录密码解密 |
| 日期、数量、类型等字段 | 按隐私目标逐项确定 | 决定索引、同步量和业务语义泄露 |
| 页面刷新与自动锁定 | 首版刷新后重解锁；闲置时长另定 | 安全与使用便利性的取舍 |
| 自动结息调整 | 解锁后补结 | 无在线解锁设备时不准时入账 |
| 家庭密钥授权人 | 明确 owner、admin 是否均可授权 | 影响邀请及密钥分发流程 |
| 家庭恢复方式 | 明确恢复责任及恢复材料保管人 | 避免最后持钥人丢失后全家庭失去访问 |
| 历史明文保留 | 明确保留周期、清理方式和责任人 | 决定历史泄漏风险何时结束 |
| 发布范围与设备基线 | 按阶段验证后交付，先确定设备与数据规模 | 决定兼容、性能和完整验收门槛 |
