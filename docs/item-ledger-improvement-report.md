# 记一笔与记物品：交互与账务口径改进报告

## 结论

应当坚持现有《记物与记账联动调整方案》的主方向：**流水是支付事实，物品是成本归集对象，配件是待消耗库存**。一笔采购只录一次金额；分类回答“钱花在什么性质的事上”，物品归属回答“这笔钱服务于什么物品”，二者是并行维度。

当前困惑的根因不在成本公式，而在前后端完成度不一致：服务端已经支持 `body`、`fee`、`accessory`、`link` 四类归属，但页面仍把关联物品作为“仅追溯”的简单标签；物品页仍要求再次手填本体价和配件单价。因此用户看见的是两套金额和两个入口，而不是一条采购主线。

## 财务口径

| 概念 | 唯一来源 | 应如何展示 |
| --- | --- | --- |
| 支付金额、账户余额、分类支出 | 流水 | “本月支出”和账户余额只读取流水 |
| 物品总支付 | 归属到该物品的 `body`、`fee` 与配件采购 | 展示构成与来源流水 |
| 当前持有成本 | 本体和附加费用全额，加上已消耗的配件 | 说明“已花在这件物品上的金额” |
| 剩余库存价值 | 未使用配件的单价 × 剩余数量 | 单独展示，不混入已消耗成本 |
| 分类 | 流水分类 | 不从物品归属反推，也不因为关联物品而改变 |

这一区分符合成本归集原则：付款只发生一次，分摊不会再次改变账户余额；同一笔钱可以同时出现在“日用百货支出”和“电动牙刷总支付”两种视图中，但不能被当作两笔支出。

## 现有实现与方案的差距

服务端数据模型已具备大部分基础：`transaction_items` 有 `role` 与 `accessory_id`，`TransactionsService` 可以内联创建物品或配件批次，并校验配件金额等于单价乘数量；`CostService` 也已经把本体、附加费用和配件库存纳入统一成本公式。

前端仍停留在旧模型：

- `NewTransactionView.vue` 只发送 `itemId` 与分摊金额，默认得到 `link`，页面还明确提示“成本指标仍由物品采购价与配件批次计算”。
- `ItemFormView.vue` 同时要求填写本体价和配件单价，导致用户必须重录已在流水中填写过的金额。
- `ItemDetailView.vue` 把关联流水称为“用于对账，不重复计入成本”，没有解释金额来源或未分摊差额。

还有一个必须先修复的数据模型冲突：目前 `transaction_items` 对 `(transaction_id, item_id)` 唯一，服务端也禁止同一物品在同一笔流水出现两次。因此“牙刷本体 ¥400 + 同一笔里的刷头 ¥240”不能同时分配给同一个物品，和原方案的核心示例相冲突。

## 推荐交互

### 1. “记一笔”是默认入口

保留现有金额、账户、分类、时间、备注的主表单。支出表单底部只放一个折叠区：**“这笔支出要归属到物品吗？”**。

- 默认不展开：普通账，零额外步骤。
- “新物品”：内联填写名称、物品分类、预期寿命；金额默认继承整笔或填写拆分金额。
- “已有物品”：选择物品后再选用途：本体追加、配件补货、附加费用、仅关联。
- “配件补货”：填写数量，系统只读显示反算单价；不再同时要求用户填写总额和单价。
- “多件商品”：可添加多行，始终显示“已归属 / 未归属”。未归属部分允许存在，但明确说明它不进入任何物品成本。

示例：超市支付 ¥640，只录一笔支出；归属行是“电动牙刷 · 本体 ¥400”和“电动牙刷 · 配件刷头 ×12 ¥240”。账户只减少 ¥640，物品总支付也为 ¥640，剩余 10 个刷头显示为 ¥200 库存。

### 2. “录入物品”改为补充入口

物品页不应再默认收集另一份购买金额。首屏让用户选择：

1. **从本次支出创建**：跳入预填的“记一笔”，保存时原子创建流水与物品；
2. **关联已记流水**：选择最近的支出及其可用未归属金额；
3. **暂不关联**：用于礼物、历史补录或估价，保留手填回退价，并在详情页标记“未关联流水”。

这比让物品页先创建、再用第二次请求补流水安全：同一笔采购与物品绑定必须在一个数据库事务中完成，失败时不能留下只建了物品或只记了流水的半条记录。

### 3. 物品详情变成“成本构成”页

顶部依次呈现：总支付、当前持有成本、剩余库存价值。其下列出来源：本体、每个配件批次、附加费用，以及各自的来源流水和日期。存在手填回退价或关联流水未归属金额时，用醒目但不阻断的提示说明差额，并提供“补记 / 调整归属”动作。

## 必须先落实的完整性规则

1. 将同一流水对同一物品的唯一约束从 `(transaction_id, item_id)` 改为可表达不同归属行的键，例如包含 `role` 和配件批次；服务端去重也按“物品 + 用途 + 批次”判断，不能只按物品 ID 判断。
2. `body`、`fee` 全额进入持有成本；`accessory` 必须绑定一个批次，并由“分摊金额 ÷ 数量”反算单价；`link` 只提供关联，不进入成本。
3. 多行分摊总额不得超过流水金额。差额是“未归属支付”，在流水与受影响物品上均可见，但不自动塞入成本。
4. 已产生配件消耗后，不允许悄悄修改批次数量、单价或来源分摊；应走调整或冲销流水，保留审计链路。
5. 退款、退货不应依赖删除原流水。后续版本应增加可追溯的退款/冲销归属，明确关联原采购；删除只适合误录且尚未被业务使用的记录。

## 分期实施

| 阶段 | 交付 | 验收标准 |
| --- | --- | --- |
| P0 | 详情页显示来源、未归属金额和“手填回退价”标记 | 不再静默展示两套金额 |
| P1 | 修正同流水同物品多归属的约束；完成“记一笔”中的用途、内联新物品、配件批次表单 | ¥640 可拆为本体 ¥400 + 配件 ¥240，账户只减少一次 |
| P2 | 物品页改为“从支出创建 / 关联已记 / 暂不关联”三选一 | 新建物品默认不再重复录价 |
| P3 | 退款/冲销、历史数据对账队列、详情页成本演进说明 | 历史数据不改数；每个差额都有可解释来源 |

## 回归用例

- 普通午餐 ¥30：只有流水和分类，无物品归属。
- 新买牙刷 ¥400：一笔支出创建一件物品，`body` 为 ¥400。
- 牙刷与刷头同单 ¥640：同一流水可对同一物品写入 `body` ¥400 与 `accessory` ¥240；12 个刷头、已用 2 个时，总支付 ¥640、持有成本 ¥440、库存 ¥200。
- 只补刷头 ¥240：选择物品、配件、数量 12，单价自动为 ¥20。
- 获赠物品：无流水，使用回退价且页面明确标注。
- 已消耗配件后退款：拒绝静默修改，要求走冲销或先撤销消耗。

## 本次界面修复

流水列表筛选区在桌面端已改为内容宽度布局：日期、类型、账户、分类、关键词与“查询 / 重置”不再平均占满整行；窄屏仍维持两列，保证触控可用性。
