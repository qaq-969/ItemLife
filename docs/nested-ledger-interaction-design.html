多级子账单与物品树

每一次付款只是一条根流水；商品、物品、配件与附件都作为可展开的归属节点。删除按金额归属联动，并生成可追溯的 revert。

设计结论

“记一笔”是唯一创建入口；物品页只负责查询、使用、维护结构和发起调整。子账单不是第二笔钱，而是根流水内部的金额归属树。这样账户余额只由根流水变动一次，物品成本却能精确追溯到任意层附件。

一笔钱，一条根流水根节点记录账户、分类、时间、付款金额；只有它影响现金余额。
任意层子账单一件物品可有附件，附件也可再有附件；每个节点都可继续拆分金额与数量。
删改留痕删除按归属行同步物品与流水；共享流水只扣减受影响金额，同时保留审计与 revert 记录。

主界面：记一笔

记账与记物使用同一个支出表单：物品清单为空就是普通记账，添加新建物品或关联物品后即形成可追溯的物品归属树，不再要求用户先选择模式。

删除联动：按金额归属处理并保留审计

用户明确删除物品或流水时，系统按归属行联动，而不是删除整个关联网络。删除物品会移除它在所有流水中的本体、配件和附加费用，并扣减共享流水金额；删除流水会删除由它创建的物品，并撤销它追加到既有物品的配件。共享流水金额减至 0 时才删除整笔，操作同时生成审计与 revert 记录。

无现金退款：报废 / 录入错误

新建内部库存调整：减少该批次剩余数量与库存价值，不改变账户余额；根流水时间线显示“已由 revert #R-002 调整”。

有现金退款：退货 / 商家返款

新建一笔收入或原支出的冲销流水，选择收款账户并引用原采购；账户余额和物品成本同时按规则回退。

跨流水示例：流水 A 购买电动牙刷，流水 B 同时购买剃须刀和牙刷刷头。删除流水 A 时，电动牙刷及流水 B 中依附于它的刷头归属一并删除；流水 B 保留剃须刀，并实时扣减刷头金额。退款、退货仍应走退款或冲销流程。

数据与实现约束

对象建议结构目的
根流水保留现有 transactions；仅根节点有账户和现金方向。账户余额、分类统计和支付事实不重复。
子账单节点新增可自引用的归属节点：parent_node_id、金额、用途、物品/批次引用、排序与状态。表达任意层物品、附件和费用树。
物品结构物品增加可空 parent_item_id；库存批次仍保留数量、单价和消耗审计。让物品页按同一树查看，但不将父子关系误当作新的付款。
revert记录 reverts_node_id、原因、创建人和时间；退款额外引用原根流水。审计可追溯，避免改写历史。

全局控件与响应式约束

所有页面的选择器、单选、多选、开关、日期时间选择和弹窗均使用项目自定义组件；禁止新增原生 select。文本、金额和数量输入保留原生输入语义，但统一由项目样式和校验规则呈现。

移动端表单优先采用两列栅格；名称、备注等长文本可独占一行。操作按钮按内容收缩，不强制占半行。
桌面端表单容器设置最大宽度；树节点用连接线、层级标签和缩进表达关系，避免横向空白拉伸。
统一组件AppSelect、AppCheckbox、AppRadioGroup、AppDateTimePicker、AppModal 全站复用，保证键盘与触屏行为一致。

建议实施顺序

第一期：交互骨架记一笔展开子账单树；物品页移除“录入物品”入口，改为“在记一笔中追加”。
第二期：递归模型引入节点父子关系、同级排序、任意层附件，以及根流水不重复入账的校验。
第三期：revert处理报废、退货、数量调整和历史关联视图；为已使用库存增加强约束。
