结构调研 · 2026-10-05

“设置”与“我的”统一方案

目标是让用户只记住一个个人管理入口，同时保证账户、分类、家庭、安全和站点管理最多两次点击可达，并让桌面端与移动端采用同一套信息结构。

结论

建议保留“我的”，撤销独立“设置”主导航

“我的”升级为统一管理中心；桌面侧栏与移动底栏都只保留“我的”。账户、分类、家庭、安全、站点管理按任务分组呈现。原 /settings 保留兼容跳转，已有子页面和接口不需要重写。

现状与重复来源

桌面端

  • 侧栏同时出现“家庭”“设置”“我的”“站点管理”。
  • “设置”包含账户管理、分类管理、账号安全。
  • “我的”再次包含站点管理、账号安全、家庭、账户与分类设置。

移动端

  • 底部导航只有“我的”，没有“设置”和“家庭”。
  • 用户必须经“我的”进入管理功能，实际已形成管理中心。
  • 同一功能在桌面和手机上的路径与命名不同。
功能桌面当前入口移动当前入口主要问题
账户管理设置 → 账户；我的 → 账户与分类设置我的 → 账户与分类设置 → 账户入口重复且移动端多一层
分类管理设置 → 分类；我的 → 账户与分类设置我的 → 账户与分类设置 → 分类“设置”是页面还是分组不清晰
账号安全设置 → 安全；我的 → 安全我的 → 安全同功能两个主入口
家庭管理侧栏家庭；我的 → 家庭我的 → 家庭桌面重复、跨端结构不一致
站点管理侧栏站点管理；我的 → 站点管理我的 → 站点管理管理员看到两个入口

方案比较

推荐

A. 合并到“我的”

跨端完全一致；用户只需记住一个入口；对子页面改动最小。

清晰度最高，迁移风险低

B. 保留两者并重新命名

“我的”只管身份，“账本设置”管账户与分类。

安全、家庭、站点管理仍难明确归属

C. 侧栏设置抽屉

不离开当前页即可配置，但手机和桌面需要两套交互。

实现成本高，当前功能量不值得

推荐的信息结构

“我的”分组内容展示规则
账户身份显示名称、邮箱、两步验证状态所有用户
账本设置账户管理、分类管理所有用户；两个入口直接进入子页面
家庭与协作家庭管理、邀请与成员所有用户

会话退出登录放在页面末尾，避免与设置项混淆

路由与实施建议

统一导航

桌面侧栏移除“设置”“家庭”“站点管理”的重复主入口，仅保留“我的”；移动底栏不变。

重组“我的”

将现有入口按账本、协作、安全、管理分组；账户与分类直接进入对应页面，减少一层跳转。

兼容旧地址

/settings 重定向到 /me；账户、分类、安全、家庭与站点管理路由继续保留。

补齐返回关系

所有管理子页提供“返回我的”或面包屑；浏览器返回键维持原历史，不强制跳首页。

可用性与验收标准

  • 桌面和移动端的管理入口都命名为“我的”。
  • 每个功能只有一个主要入口，账户、分类、家庭、安全最多两次点击可达。
  • 管理员功能按角色显示，不留下无权限空分组。
  • 分组使用真实标题和说明，不只依赖图标或颜色表达。
  • 列表行触控高度至少 44px，键盘焦点清晰，当前页同时用背景和文字状态表达。
  • 旧的 /settings 地址仍可使用，不产生 404。

证据范围

本报告检查了当前 AppShell.vue、MeView.vue、SettingsView.vue 和路由配置，结论针对现有信息结构与入口关系。当前运行环境没有可操控的登录态浏览器截图工具，因此未将像素级布局、键盘焦点和屏幕阅读器行为表述为已验证结果；这些项目应在实施后通过桌面与手机实机复核。
